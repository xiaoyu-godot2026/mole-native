## v3.6 改了什么

- **诊断不再写剪贴板**（删了 `Diag.publish` 里的 ClipboardManager 逻辑，也顺手解决「结算覆盖用户复制内容」这个老问题）。
  现在分四处进 logcat，标签统一 **`MoleDiag`**：
  - `boot dev=… scr=… ver=…` —— 每次启动一行
  - `evt <tag> <msg>` —— 实时事件（start / map / rewind / jump / resync / skipnotes / bgm …）
  - `[over] …` / `[quit] …` / `[bootfail] …` —— 结算、放弃、启动失败的完整摘要（分块，每块 ≤3000 字符）
  - `CRASH <线程>` + 栈 —— 崩溃；下次启动再补一条 `[prevcrash]`
  读法（**设备命令里不能带管道**，过滤放本地）：
  ```bash
  /root/dsh-bin/dev "logcat -d -t 3000" | grep MoleDiag            # 最近 3000 行里筛诊断
  /root/dsh-bin/dev "logcat -d -b crash -t 200" | grep MoleDiag    # 崩溃缓冲
  ```
  坑：`logcat -d -s MoleDiag` 会被设备策略拦（`-s` 被判成「改缓冲区」），别试；`-b crash` 是允许的。
  文件备份仍在 App 私有目录 `files/diag.log`（读不到，只作现场保留）。
- **设置面板底部加版权标注**：`角色原型 ZipZipPipe · 美术/音乐：AI 生成 · 非商用`，
  「完成」按钮上移 0.015ph 给这行让位。完整说明见 `docs/致谢与授权.md`。
- 版本号 3.5.2(20) → **3.6.0(21)**。

## v3.5 改了什么

- **暂停 / 主界面**：对局中右上角齿轮左边多一个暂停键（两竖线）；面板两个按钮「继续 / 回主界面」。
  暂停时时钟冻结、音乐暂停（音游），恢复时把墙钟基准挪回暂停点，不乱跳。
- **返回键接管**（`MainActivity.onBackPressed`）：设置里→关设置；暂停中→继续；对局中→弹暂停；结算→回主界面；
  主界面再按才退出 App。
- **放弃本局**不计分、不写最高分、不写诊断（`exitToMenu`）。
- **谱面加密**（`buildChart`）：弱拍从「每两拍出一次」改成「75% 出」（`hash(k*13+5) > 0.25`，
  hash 均匀分布；早期文档写的 82% 是笔误），
  留白 10% → 6%；多拍盆概率放大：强拍 hh>0.88 → 3 拍、hh>0.55 → 2 拍（原 0.90/0.72），
  中拍 hh>0.80 → 2 拍（原 0.92），弱拍 hh>0.93 → 2 拍。
- **判定偏移不动**：实测 mean −5 ms / 中位 0 ms（n=114），基准是对的，`judgeOffset` 保持默认 0。

### v3.5.1 修的两个问题

- **暂停/设置后突然冒出一堆鲸鱼**：根因是音乐进度估算（`positionMs` 平滑）在暂停期间把
  `lastRawPos + (now-lastRawAt)` 越算越远，恢复后 `songPos()` 的单调钳制把这个跳变锁死，
  `tickRhythm` 于是把这段时间到期的音符一口气全生成。修法：
  `resyncRhythmClock()` 在「暂停继续 / 关设置 / 切回前台」时把时钟对回音乐真实位置，
  并把已过期音符（`t + W_GOOD < pos`）直接跳过；`songPos()` 再加一道 >700ms 跳变兜底。
  诊断里会留 `resync` / `skipnotes` / `jump` 事件。
- **绿盆看不懂要点几下**：绿盆=连敲 2 下、蓝盆=连敲 3 下。现在盆沿画一个圆形数字徽标
  （剩余敲击数，敲一下减一），主界面加一行图例「银盆敲 1 下 · 绿盆连敲 2 下 · 蓝盆连敲 3 下」。

### v3.5.2 修的问题（音游模式）

- **根因：背景音乐 `isLooping = true`**。曲子播完自动从头循环，`songPos()` 的单调钳制把时钟卡在曲尾，
  于是「音符打完了不结算」；暂停回来撞上循环回卷，时钟被 resync 拽回开头，就出现
  「谱面重来、鲸鱼娘没了、点水面还扣分」。三件事是同一个根。
- `GameAudio.setLooping()`：**音游开局关循环**，回菜单/经典再打开（菜单要循环）。
- 结算改为双条件：`nowMs >= durationMs` **或** 播放器回报 `completed && nextBeat >= chart.size`。
- 时钟兜底：`songPos()` 检测到播放器回卷 > 300ms → `wallOnly` 墙钟接管并记 `rewind`，
  保证这一局一定能走到结算；`resyncRhythmClock()` 只接受 200ms~5s 的向前推进，回卷一律不认。
- **放弃本局也写诊断**：暂停面板点「回主界面」= `exitToMenu()` → `diagDump("quit")`，
  以后中途退出也能读到音游数据（以前只有打完才写）。
- **多拍盆保底轮转**：`chart.size % 9 == 4` 强制蓝盆、`% 4 == 2` 强制绿盆，
  不再靠能量分布碰运气（之前几乎不出蓝）。离线模拟 269 拍：音符 ~145、敲击 ~230、
  银 59~91 / 绿 38~63 / 蓝 16~24，约 1.7~2.0 次/秒。

## 两种模式（当前全部数值）

| 项 | 音游模式 | 经典模式 |
|---|---|---|
| 时长 | 整首歌 | 30 秒 |
| 背景音乐 | 从头播 | 播放中静音 |
| 音效 | 全部关闭 | 开 |
| 记分 | 基础 ×(1.0 / 0.62) + min(连击/10, 5) | 基础 1/3/5，连击每 3 个 +1（上限 +3） |
| 失误 | −4 分 + 断连 | −1 分 + 断连 |
| 最高分 | prefs `best` | prefs `bestC` |

- 判定：Perfect ±85 ms（×1.0，音高 1.0）；Good ±165 ms（×0.62，音高 0.84）
- 盆：银 1 拍 10 分 / 绿 2 拍 50 分 / 蓝 3 拍 30 分
- 谱面：3 轨 = 3 列，右→左滚动，提前 2600 ms 可见，播放头在 17%
- 音频默认：音效 20% / 音乐 50%（`volVer=2` 迁移）
- 背景音乐策略：**开始界面一直响**；音游模式 = 歌曲本体（不受开关影响）；结算静音；**经典对局看设置里的「音乐 开/关」**（默认关 = 保持原手感）
- 设置面板底部一排三个按钮：内置 / 震动 / 音乐（实心=开）

## 诊断通道（v3.6 起走 logcat）

- 事件、结算摘要、崩溃栈全部写 **logcat，标签 `MoleDiag`**；设备 shell 读：
  `dev "logcat -d -t 3000" | grep MoleDiag`（崩溃用 `-b crash` 缓冲；`-s` 过滤会被策略拦）。

### 性格（拟稿，**待用户确认/补充**）

游戏里的性格是靠「挨打反应」立起来的，所以核心就是一条：**明明在努力工作，却天天被敲头**。

- **勤快但倒霉**：戴着小鲸鱼围裙上岗，端着自己的铁饭盆，一冒头就被敲
- **呆萌、反应慢半拍**：出来是先乐呵呵地笑着，不是警觉地盯着你
- **小傲娇**：挨第一下不是哭，是生气——抱臂、皱眉、头上冒青筋，一副「你干嘛啊」
- **一戳就破防**：再挨一下就撑不住了，直接揉眼睛哭
- **彻底晕菜**：被敲到底就漩涡眼、冒光环，左右晃两下沉回水里
- **不记仇**：晕完沉下去，下一轮冒出来又是那张笑脸
- **皮实**：蓝盆要连敲三拍才碎，说明它抱着盆死撑到底，是挨打界的硬骨头

待补：台词 / 口头禅（目前游戏里没有任何文字台词，只有系统和数字）。

### 音效（9 个，`art/gen_audio.py` 合成，无第三方依赖）

采样率 22050 Hz、单声道、16 bit。设计目标：**尾巴 120ms 内收干净**——
128 BPM 一拍只有 466ms，尾巴一长快速连打就糊成一团。

| 文件 | 用途 | 设计 |
|---|---|---|
| `sfx_hit1.wav` | 敲第 1 下 | 880 Hz 金属短击，衰减 95ms |
| `sfx_hit2.wav` | 连打第 2 拍 | 988 Hz，比第一下亮 |
| `sfx_hit3.wav` | 敲碎 | 740 Hz 金属 + 低频冲击 |
| `sfx_knock.wav` | 盆被打飞 | 扫频噪声 + 金属下坠，0.5s |
| `sfx_dizzy.wav` | 打晕 | 820→250 Hz 下滑 + 颤音 + 一下叮 |
| `sfx_miss.wav` | 漏敲 / 敲空 | 62 Hz 闷响，0.16s |
| `sfx_combo.wav` | 连击 | 784 / 1046 / 1319 Hz 上行三连 |
| `sfx_start.wav` | 开局 | 523 → 784 Hz 上行两音 |
| `sfx_over.wav` | 结束 | 784 / 587 / 392 Hz 下行三音 |

**判定差异靠变调**：Perfect 用原调（1.0），Good 用 0.84 倍速（低半档），不看屏幕也能听出准没准。

## 5. 玩法 · 音游模式

### 5.1 节拍识别（`Beat.kt`，全本地，不上传）

```
MediaExtractor + MediaCodec 解码 → 每 512 采样求一次能量（≈86 Hz 包络）
  ↓
novelty[t] = max(0, ln(1+E[t]) - ln(1+E[t-1]))   # 能量外差，去均值后半波整流
  ↓
自相关，滞后 0.26 ~ 1.50 s（≈ 40~230 BPM）→ 取峰值 → 抛物线插值细化 → BPM 折回 75~180
  ↓
相位：在 0..lag 里找使拍点处 novelty 之和最大的偏移
  ↓
每拍强度：该拍窗口内 novelty 均值，归一化到 0~255
```

- 结果缓存：SharedPreferences key `beat_v2_<uri或builtin>`，同曲第二次直接读
- 识别失败 → 按 **120 BPM / 500ms 一拍 / 强度 128** 兜底，开场红字提示
- **边界**：假设全曲速度恒定；变速曲、自由节奏（古典/氛围/清唱）会失准

### 5.2 谱面生成（`buildChart`）

按拍点逐拍决定「出不出的、出哪格、敲几下」，开局一次性排完：

| 拍的能量 | 规则 |
|---|---|
| > 165（强） | 每拍都出；28% 概率变成连打（18% 两下 / 10% 三下） |
| > 95（中） | 每拍都出；8% 概率两下 |
| ≤ 95（弱） | 每两拍出一次 |

- 另有 10% 的固定伪随机留白（`hash(k) < 0.10`），避免机械感
- 选格子：按 `hash(k)` 轮转起点，跳过刚用过的列；每个格子有 `busy` 记录，被占用到
  `t + (hits-1)×period + 1260ms` 才放行（覆盖死亡动画 + 下沉）
- 开头跳过前 1200ms（`START_SKIP_MS`）

### 5.3 时序与判定

| 常量 | 值 | 含义 |
|---|---|---|
| `LEAD_MS` | 460 | 提前多久开始冒头 |
| `SETTLE_MS` | 70 | 提前多久到达判定位置 |
| `W_PERFECT` | ±85 ms | Perfect 窗口 |
| `W_GOOD` | ±165 ms | Good 窗口 |
| `MISS_PENALTY` | 4 | 漏敲/敲空扣分 |

**核心设计**：地鼠升到水面那一帧 = 音符判定时刻。玩家看到冒头就敲，敲下去正好卡在鼓点上。

### 5.4 计分

```
得分 = 基础分 × 判定倍率 + 连击加成
基础分：银 10（1 下）/ 蓝 30（连打 3 拍）/ 绿 50（连打 2 拍）
判定倍率：Perfect 1.0 / Good 0.62
连击加成：min(连击 / 10, 5)
漏敲或敲空：扣 4 分（最低 0）并清空连击
```

结算显示：精准数 / 良好数 / 漏掉数 / 准确率 / 最大连击。

### 5.5 谱面轨道（`drawChart`）

屏幕上方三条轨道，对应三列格子：

- 音符从右往左滑，金色竖线是**判定线**（在轨道 17% 处）
- 可视范围 **未来 2.6 秒**
- 音符颜色 = 盆的颜色；**长条 = 连打几拍**
- 位置：`hudH + dp(5)` 到 `skyH` 之间，高度取两者的 56%

### 5.6 死亡动画（两种模式共用）

盆飞走 → 原表情定格 **340ms** → 换晕脸 + 左右摇两下 **620ms** → 下沉 **150ms**

## 6. 玩法 · 经典模式

就是 v1.8 的老玩法，**进游戏后没有背景音乐**：

- 一局 30 秒（`ROUND_MS = 30000`）
- 铁盆三档（颜色 = 血量）：银 1 下 / 绿 2 下 / 蓝 3 下，概率 50% / 20% / 30%
- 基础分：银 1、蓝 3、绿 5；连击每满 3 下 +1（封顶 +3）
- 敲空扣 1 分并清空连击
- 出怪间隔 `max(360, 830 - 得分×11) ms` + 随机 0~180；同屏最多 3 只
- 铁盆被打飞：重力 1500 dp/s²，初速横向 90~220 dp/s、向上 420~580 dp/s，带自旋

两个模式的最高分**分开记录**（`best` / `bestC`）。

## 8. 代码地图

```
app/src/main/kotlin/com/xiaoyu/molenative/
  MainActivity.kt    全屏沉浸、生命周期、选歌 onActivityResult（约 90 行）
  GameView.kt        全部玩法与绘制（约 1965 行）
  Audio.kt           GameAudio：SoundPool 音效 + MediaPlayer 背景音乐（约 373 行）
  Beat.kt            BeatMap + BeatDetector：解码/包络/自相关/缓存（约 324 行）
  Diag.kt            每局诊断 / 崩溃记录 / 写 logcat（TAG=MoleDiag，约 274 行）
```

`GameView` 要点

- `Phase { READY, PLAYING, OVER }`、`Mode { RHYTHM, CLASSIC }`
- `Cell { active, state, p, hit0, hitsTotal, basinHp, basinColor, face, dieAt, retreatAt, bornAt, … }`
  - `state`：0 = 带盆站立，2 = 漏了正在沉，3 = 已晕（锁死）
  - `face`：0 开心 1 生气 2 哭，3 = 晕（只在死亡时出现）
  - `basinHp`：剩余要敲的拍数（v3.0 起语义从「血量」变成「连打拍数」）
- 绘制顺序：`drawSea` → **`drawChart`（仅音游）** → `drawBoard`（洞口 + 人物 + 水面前沿）
  → `drawFx` → `drawFlyBasins` → `drawHud` → 覆盖层/设置面板
- 关键几何：`charW = cellW*0.90`、`rx = cellW*0.47`，**必须保证 charW < 2*rx**，
  否则人物底线会露在洞口阴影外面
- 状态栏/挖孔：`setOnApplyWindowInsetsListener` 取 `displayCutout.safeInsetTop`，绘制整体 `translate(0, insetTop)`
- 时钟：音游模式用**音乐播放进度**（平滑后）当全局时钟，经典模式用系统时钟；
  打开设置时不更新 `nowMs`，等于全场景冻结

## 10. 坑与已知问题

1. **ADB / 设备 shell 连不上**：Shizuku 服务本身正常，但客户端一直 `bound=false, binding=true`，
   拿不到 logcat。临时办法：`onDraw` 里 try/catch 把堆栈画成白字黑底，让用户截图。
2. **启动崩溃疑云**：`setOnApplyWindowInsetsListener` 早于 onLayout 触发，`RadialGradient` 半径为 0 会抛异常。
   已用 `width < 8` 早退 + `max(1f, …)` 半径兜住。
3. **洞口与人物交叠**：人物比洞口宽时，被裁的直边会露在阴影外，看起来很怪。
   现在加宽洞口 + 收窄人物 + 水面前沿（下半个椭圆盖在人物身上）解决。
4. **美术管线**只能用 sharp（`NODE_PATH=/usr/local/lib/node_modules/@deepseek-ai/dsh/node_modules`）。
   sharp 的 `.composite()` 与 `.resize()` 顺序会被重排，负偏移会报同尺寸错误，需分两次处理、先裁后合。
5. **音效尾巴**：早期音效衰减 0.45s，128 BPM 下每拍 466ms，连打直接糊成一片。
   现在统一控制在 120ms 内。
6. **改内置曲必须换缓存前缀**：`beat_v2_` 这层前缀就是干这个的，否则会拿旧曲的拍点表打新曲。
7. **MediaPlayer 的进度会跳**：`positionMs()` 做了平滑 + 单调钳制，否则动画会抖。
