## 五、发现的问题（按严重度）

### P0 · 文档比远端新，4 项没推
`python3 tools/release.py check`：

```
待推送 2 个：M README.md、M docs/项目档案.md
待删除 2 个：D docs/状态卡.md、D docs/资产档案.md
```

后果：远端 main 的 README 还指向已删除的 `docs/资产档案.md`，新对话按远端 clone 会读到死链。**这是唯一必须动手的事。**

### P1 · README 版本号停在 3.3(15)
实际 3.5.2(20)，手机装的也是 20。README 首屏那条「当前版本」会骗人。

### P1 · 档案代码地图过期
- 写「GameView.kt 1660~1870 行」，实际 **1965 行**；Kotlin 总计 3005 行。
- 代码地图漏了 **Diag.kt（253 行）**，而 v3.5.2 的诊断/崩溃/剪贴板全靠它。

### P1 · 存档键表漏 `musicOn` 与 `diag`
见 3.1。

### P2 · 音量默认值有两套
`Audio.kt` 内联默认 `sfxVol 0.85 / bgmVol 0.32`，靠 `volVer<2` 迁移强制刷成 0.20/0.50。行为上没问题，但两处真值；将来谁清掉 volVer 就会悄悄回到 0.85/0.32，和文档打架。

### P2 · 签名私钥 + 密码在公开仓库
`keystore/mole.p12` 与 `app/build.gradle` 里的 `mole2026` 都是公开的，任何人可签出同包名的「升级包」。对自娱自乐的小游戏是可接受取舍，但要明确知道：这层防不了伪造。

### P3 · 历史崩溃 5 次（已过期）
`logcat -b crash` 里 5 条 `IllegalArgumentException: ending radius must be > 0`，栈顶 `GameView.layoutNow`，时间全在 **10-25 21:31**，早于 v3.5（CI 首建 v3.5 于 10-26 01:02）。当前源码已有 `width<8/height<8` 早退 + `max(1f/2f)` 半径 + try/catch，且 v3.5.2 装机后**无新崩溃记录** → 判定为已修，但缺一次真机确认。
