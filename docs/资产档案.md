## 1. 角色设定

**鲸鱼娘**（用户自有角色，图由用户用豆包生成，只做工程不做画）

**外观**
- 蓝紫渐变长发，白色女仆头饰 + 女仆装，白色荷叶边围裙，围裙上有一个小鲸鱼图案

- 主色：头发 #3B4C9A→#7FB6E8 渐变，衣服白/深蓝，围裙白

**四张表情**（canonical 画布 613×617，头部质心固定在 (305,176)）

## 2. 美术资产

**成品图**（都在仓库 `app/src/main/res/drawable-nodpi/`）

| 文件 | 尺寸 | 说明 |
|---|---|---|
| `char_happy/angry/cry/dizzy.png` | 613×617 | 同一画布、同一头部位置，按头部面积归一化 |
| `basin_grey/blue/green/red.png` | 516×277 | 铁饭盆四色，已裁边；红色当前未使用 |
| `mipmap-*/ic_launcher*.png` | 各密度 | 由「盆扣头」图和蓝色渐变生成 |

**绿幕抠图参数**（用户给的是纯绿底图）
- 绿度 `gn = g - (r+b)/2`，alpha 线性过渡 `LO=26 → HI=62`
- 反预乘 `fg = (obs - (1-a)*bg)/a`，其中 `ad = max(a, 0.34)`
- 去溢色 `fg = min(fg, (fr+fb)/2 + 8)`
- **教训**：白底/棋盘底抠不干净（发缝里留白斑），必须让用户出纯绿底

**归一化**：按头部面积缩放到统一画布，结果写在 `art/canon.json`：
`{"CW":613,"CH":617,"HX":305.35,"HY":176.01}`

## 3. 玩法数值（v1.8）

- 场地 3×3 格，一局 **30 秒**
- 铁盆三档（颜色 = 血量）：**银 1 下 / 绿 2 下 / 蓝 3 下**，出场概率 50% / 20% / 30%
- 基础分：银 1、蓝 3、绿 5；**连击每满 3 下基础分 +1**（封顶 +3）
- 失误：敲空 **扣 1 分**（最低 0）并清空连击
- 表情：挨 0/1/2 下 → 开心 / 生气 / 哭
- 死亡三段：盆飞走 → **原表情定格 340ms** → 换晕脸 + 左右摇两下 620ms → 下沉 150ms
- 出怪间隔：`max(360, 830 - 得分×11) ms` + 随机 0~180；同屏最多 3 只
- 铁盆被打飞：重力 1500dp/s²，初速 90~220dp/s 横向、420~580dp/s 向上，带自旋
- 最高分存 SharedPreferences（name = `mole`）

## 4. 代码结构

```
app/src/main/kotlin/com/xiaoyu/molenative/
  MainActivity.kt   仅 setContentView(GameView)，包在 try/catch 里，失败时显示堆栈
  GameView.kt       ~820 行，全部逻辑与绘制
```

`GameView` 要点
- `Phase { READY, PLAYING, OVER }`
- `Cell { active, state, bornAt, stateAt, liveUntil, retreatAt, dieAt, basinHp, basinColor, face, p }`
  - `state`：0 = 带盆站立，3 = 已晕（锁死，再敲不加分不换脸）
  - `face`：0 开心 1 生气 2 哭，3 = 晕（只在死亡时出现）
  - `p`：0~1 出场/入水进度
- 绘制顺序：`drawSea` → `drawBoard`（洞口 + 人物 + **水面前沿**）→ `drawFx` → `drawFlyBasins` → `drawHud`
- 关键几何：`charW = cellW*0.90`、`rx = cellW*0.47`，**必须保证 charW < 2*rx**，否则人物底线会露在洞口阴影外面
- 状态栏/挖孔：`setOnApplyWindowInsetsListener` 取 `displayCutout.safeInsetTop`，绘制时整体 `translate(0, insetTop)`

## 5. 编译与发布

```bash
# 推文件（git push 走不通，必须用 REST Git Data API）
python3 art/push_files.py <文件清单.txt> "commit message"

# 查编译
GET https://api.github.com/repos/xiaoyu-godot2026/mole-native/actions/runs?per_page=1

# 取 APK
GET .../actions/runs/<run_id>/artifacts → 下载 zip → app-debug.apk
curl -G -H @/root/.dsh/.bridge_headers 127.0.0.1:3090/app/export --data-urlencode "path=/tmp/打鲸鲸-vX.apk"
```

- 凭据：`/root/.secrets/gh.cfg`（Bearer token）
- 用户自己装 APK（策略不允许 `pm install`），文件落到手机 `Download/`
- 编译一次约 1 分钟

## 6. 坑与已知问题

1. **ADB / 设备 shell 连不上**：Shizuku 服务本身正常，但客户端一直 `bound=false, binding=true`，拿不到 logcat。
   临时办法：`onDraw` 里 try/catch 把堆栈画成白字黑底，让用户截图。
2. **启动崩溃疑云**：`setOnApplyWindowInsetsListener` 早于 onLayout 触发，`RadialGradient` 半径为 0 会抛异常。
   已用 `width < 8` 早退 + `max(1f, …)` 半径兜住。
3. **洞口与人物交叠**：早先人物比洞口宽，被裁的直边露在阴影外，看起来很怪。
   现在加宽洞口 + 约 4% 收窄人物 + 水面前沿（下半个椭圆盖在人物身上）解决。
4. **美术管线**：只能用 sharp 处理（`NODE_PATH=/usr/local/lib/node_modules/@deepseek-ai/dsh/node_modules`）。
5. `sharp` 的 `.composite()` 与 `.resize()` 顺序会被重排，负偏移会报同尺寸错误，需分两次处理、先裁后合。
